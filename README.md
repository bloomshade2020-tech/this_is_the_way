# DIN // COMMS v0.4 — 返信ブリッジ（実験）

**v0.3のGmail受信を維持**し、ChatGPTの既存通知部屋へ返す導線を追加しました。ChatGPTのAPIから既存チャットに直接書き込む機能はありません。GitHub Pagesの同じ6ファイルを上書きしてください。

## 新機能

1. 「設定 → ChatGPT部屋へのリンク」に**通知部屋のチャットURL**を登録します（例：`https://chatgpt.com/c/チャットID`。共有リンクではなく、自分の既存チャットを開いてアドレスをコピーしてください）。登録済みならそのまま使えます。
2. 通信画面に返信を書き、**「コピーしてChatGPTを開く」** をタップ。返信文をiPhoneのクリップボードにコピーして、登録したチャットを開きます。**ChatGPTで貼り付けて送信**してください。コピー不可なら部屋へ移動せず案内を出します。
3. DIN COMMSへ戻ると「送信した（履歴に記録）」または「まだ送ってない」を選べます。**実際の送信を自動検出していません**。送信できた時だけ「送信した」を選んでください。
4. ChatGPTでディンからの返答が届いたら「ディンの通常返答を貼り付ける ＋」から**手動登録**できます。これはGmail経由では取得できません。
5. 「入力済みで開く（実験）」は**非公式なiOS ChatGPT URLスキーム**を使用。既存チャットで入力欄に入るかどうかは環境に依存し、動かない場合もあります。返信はURLクエリに入るので、秘密の内容はこの実験で扱わないでください。**入力済みでも自動送信はされません。**最初は無害なテスト文だけで確認してください。

## 大事な注意

- Gmailの自動取得は引き続き**定期タスクが生成したメール**のみ。通常のChatGPT返答やあなたの返信はGmailから自動取得できません。
- コピーした後もChatGPTへ**自動送信しません**。DIN COMMSに履歴を記録する操作も送信ではありません。
- アプリの更新で念のため「設定 → JSON書き出し」によるローカルバックアップを推奨します。保存キー `din-terminal-v01` は変更していません。
- 公開GitHubにはAPIキー、Gmailアクセストークン、RP全文などをアップロードしないでください。
- iPhoneの「ホーム画面に追加」版は外部リンクの開き方がSafariと異なる場合があります。問題があれば画面の「コピー」と「通知部屋を開く」を分けて試してください。

# v0.3から引き継いだGmail受信機能

v0.2の見た目（ロック画面・ホーム・通信・RP・外）を維持し、**Gmailから「ディンからの通信｜This is the way」タスク通知だけを手動認証後に取得する**試験機能を追加しました。

## できること / できないこと

- 可能: Gmailの通知メールからディンの通信本文を取得し、通信画面の左側の吹き出しに表示します。
- 可能: 取り込み済みメールIDをブラウザ内に保存し、**二重登録を防止**します。以前の手動入力も残ります。
- 可能: 認証済み・アプリを開いている間は一定時間ごとに新着をチェックします（約2分間隔）。閉じていた間の新着は次にGmailへログインして取得できます。
- できない: iPhoneがホーム画面に戻っている間の自動受信、DIN COMMS独自のプッシュ通知、ChatGPTの通知部屋への返信送信、RPの自動共有。
- Gmail連携なしでも、v0.2同様に手動で使えます。

## 初期設定：Google Cloud

必要なもの: 普段ChatGPTのタスク通知を受け取っているGoogleアカウント、GitHub PagesのDIN COMMS。**ChatGPTにGmailを連携したこととは別の設定**です。

1. [Google Cloud Console](https://console.cloud.google.com/) を開く。初めてなら利用規約を確認。Google Cloudプロジェクトを新規作成する（例: `din-comms-personal`）。
2. 「APIとサービス」→「ライブラリ」で **Gmail API** を検索し「有効にする」。
3. 「Google Auth Platform」（または「APIとサービス」→「OAuth同意画面」）でアプリ名・サポートメール・連絡先を設定。
4. ユーザータイプは **外部**、公開ステータスは **テスト** のまま。**テストユーザーに自分のGoogleメールアドレス**を追加。
5. 「データアクセス / Scopes」で `https://www.googleapis.com/auth/gmail.readonly` を登録（Gmail全体を読める**制限付きスコープ**です）。個人のテスト用途では未審査の警告が表示される場合があります。許可内容に納得できるときだけ進んでください。
6. 「クライアント / Clients」→「クライアントを作成」→ **ウェブ アプリケーション** を選択。**承認済みのJavaScript生成元**には、DIN COMMSの公開アドレスの **オリジンだけ** を追加する。例: `https://bloomshade2020-tech.github.io`（末尾の `/this_is_the_way/` は含めない）。「承認済みのリダイレクトURI」はこのトークンモデルでは不要。
7. 作成された **クライアントID**（末尾が `.apps.googleusercontent.com`）をコピー。**クライアントシークレットは不要・使用しません。**

Googleの管理画面の項目名は変更されることがあります。可能ならWindowsのChromeでまず接続を確認してください。

## GitHub Pages更新

1. ZIPを解凍し、中にある **6ファイル**を選択（ZIP自体はアップロードしません）。
2. GitHubの `this_is_the_way` リポジトリのトップから「Add file → Upload files」。既存の同名ファイルは更新されます。「Commit changes」を押す。
3. GitHub Pagesの公開処理を待ってiPhoneでDIN COMMSを開き直す。以前の端末内の履歴は保持される想定ですが、念のためアプリの「設定 → JSON書き出し」でバックアップ推奨。
4. DIN COMMSのホーム →「設定」→「Gmailからの通信受信」にクライアントIDを入力 →「IDを保存」→「Googleで認証」。Googleの同意画面で自分のアカウントを選んで許可。
5. 「通信」を開くと取り込み済みの吹き出しが表示されます。「受信確認」で再チェックできます。

### iPhoneについて

- 「ホーム画面に追加」した独立表示のiOS Webアプリでは、Googleのポップアップ認証が開かないことがあります。まずSafariでDIN COMMSの公開URLを開いて認証テストしてください。
- **Safariとホーム画面版のデータ保存領域は別になる場合があります。** Safariで受信できてもホーム画面版へ自動共有される保証はありません。この点は実機で検証が必要です。
- 認証時のアクセストークンは**メモリ内にのみ**保持し、再起動後は認証し直します。通常、ログインを続けるためにユーザー操作が必要です。

## プライバシーに関する重要事項

- このアプリは **`gmail.readonly`（Gmail全体を読み取れる制限付き権限）** をユーザーが許可したときにだけ Gmail API にアクセスします。JavaScriptのメール検索対象は `noreply@tm.openai.com` からの件名 `[Task Update] ディンからの通信｜This is the way` に限定していますが、Google権限は件名単位に制限されません。
- GitHub Pagesリポジトリは公開です。**Googleパスワード、クライアントシークレット、APIアクセストークン、私的RPログは絶対にGitHubへコミットしないでください。**
- **クライアントIDは秘密鍵ではありません。** アプリ内に入力したIDは端末内に保存され、GitHubへ送信されません。
- 取り込んだ通信本文・リンク・下書きは端末の `localStorage` にのみ保存されます。ロック画面は演出用で、強固なパスワード保護を備えていません。端末を共有する場合は注意してください。
- メール本文が `...` で省略されている場合は、誤解を生まないようインポートしません。メールのレイアウトが変わると解析できなくなることがあります。

## 問題が起きたら

- `Google認証に失敗`：OAuthクライアントID・テストユーザー・承認済みJavaScript生成元を確認。
- `Gmail API 403`：APIが有効か、スコープを許可しているか確認。
- `0件`：通知メールがGmailに来ているか、題名が一致するか確認。最大直近90日、50件までを探索します。
- `既存メッセージが見えない`：以前と同じiPhoneホーム画面版か確認。Safariの保存領域とは独立することがあります。
- 更新しても旧版が出る：数分待ってアプリを閉じて再起動。必要に応じてSafariで公開URLを開いてバージョンを確認。

**このv0.3はUIと疑似Gmailレスポンスを使ったテスト済みですが、ユーザーのGoogleアカウント・iPhoneでの実接続は未テストです。**
