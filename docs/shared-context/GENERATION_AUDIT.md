# 返信に対応する共有文脈の確認情報

通常 HERE / COMMS の成功応答にある `sharedContext` を、その返信レコードの
`generationAudit` に保存する。本文と同じ既存の暗号化保管庫へ一度の保存で記録し、
再読込・既存の暗号化バックアップにも含める。別の保存先、保存期間、権限は追加しない。

| 経路 | 保存できる情報 | 表示 |
| --- | --- | --- |
| 通常 HERE / COMMS | `revision`, `checkedAt`, `coverage` | 通常 HERE / COMMS と明記 |
| 自発通知の受信 | 通知応答の `sharedContextRevision` | 版だけ。確認時刻・参照範囲は未記録 |
| 過去の返信・情報のない成功応答 | 推測・補完しない | 未記録 |
| 不正・過大な情報 | 生の情報を捨て、状態だけ記録 | 確認情報を記録できなかった旨 |
| BACKSTAGE / 生成失敗 | 共有文脈の成功記録を作らない | 対象外 |

HERE は既存の「…」、COMMS は DIN の返信横にある小さな「…」から確認する。
閉じている間は会話本文に監査欄を追加しない。「本文だけコピー」は従来どおり本文のみ。
確認画面の「日時・記録IDをコピー」も監査情報や本文を混ぜない。

## 記録の意味と境界

これはサーバーがその成功応答で返した確認情報の記録であり、モデルの思考内容や、
全資料を意味的に使った証明ではない。`coverage` の件数は検索対象の分割範囲を表し、
必須文脈の件数を含まない。全文履歴を読んだことを推測しない。

過去の返信を現在の状態で補完しない。通知の再受信でも既存の返信を上書きせず、
`contextVersion` や受信時刻を共有文脈の版・確認時刻の代用にしない。
通知から版が返らない経路も未記録として扱う。表示を開いても通信は発生しない。

保存形式は `version: 1`, `messageId`, `channel`, `origin`, `state` と、検証できた
上記フィールドだけ。表示時も返信 ID・モード・通常/自発の対応を確認する。
通常応答は UTF-8 JSON 4,096 バイト以内、版は `snapshot_` + SHA-256、確認時刻は
UTC ISO 形式、検索件数は現行上限 12,000 以下の整数。未知の追加フィールドや理由、
不正な件数・日時は受け入れない。確認情報が不正でも成功した返信本文は保存する。
返信の永続保存自体が失敗した場合は、確認情報だけを別に保存しない。

全文プロンプト、資料本文、認証情報は監査情報に追加保存しない。既存の共有 Doc の
イベント、`bodyHash` / `recordHash`、採用レビューは変更しない。後続のモデル入力、
通知用文脈、共有ログのエクスポートにもこのローカル情報を追加しない。
参照元・採否・会話順・返信本文を変更せず、追加の AI 呼び出しは行わない。

## 公開と検証

フロントエンドの更新だけで動作し、Worker・Google・共有文脈フラグの変更は不要。
プロトコル build は維持し、Service Worker のアセットキャッシュだけを更新する。
既存の通知生成・受信・ACK・ログ出力の条件は変えない。

`tests/shared-log/context-audit.test.cjs` は形式・返信との対応・不正値破棄と、
既存イベント/hash・通知用文脈が同一であることを検証する。
`tests/shared-log/context-audit-browser.cjs` は成功/失敗、古い返信、複数返信、
実際の暗号化保存と再読込、通知の部分情報と重複受信、本文コピー、モード分離、
保存失敗を検証する。外部応答はすべて模擬し、実 AI・Push・Drive 書込みは行わない。

実端末での公開後確認と実サーバー応答による記録は、ローカル試験とは別の確認事項。
公開前の返信の出典が後から判明したことにはしない。
