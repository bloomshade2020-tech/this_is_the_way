# 通知対応フロントエンド

通知本文を端末へ暗号化保存できた場合だけ受領ACKを送り、会話保存失敗時の全体巻戻しで通知を消さない保存処理へ変更します。停止操作の結果が不明な場合は記録を残し、確認前の再開を防ぎます。旧Workerへの通知受信・ACK・設定変更はprotocol確認で保留します。

この画面更新だけでは通知生成を開始しません。Workerがmigration-stopの場合、有効化とテストPushは拒否されます。既存の未受領本文の受信・保存・ACKと停止結果確認には状態変更が伴うため、単なる公開ヘルスチェックではありません。

通知を有効化すると、容量内のHERE/COMMS直近履歴、登録指示・資料本文・共有メモ・通知用現在地が送信されます。原文履歴は変更せず、BACKSTAGEの未採用相談や画像はsnapshotに含めません。共有履歴・場面情報から自然な連絡かを判断する設計であり、毎時送信やモデルの遵守を保証しません。

## ローカル検証

合成データ・通信モックのみ使用。保存競合、ACK失敗・再受信、ロック中受信、復旧応答消失と再起動、通知制御競合、旧Worker互換性、移行停止時の受信/テスト拒否を検証しました。

既存の共有文脈11項目、HTTP全体439000-byte事前検査とWorker440000-byte境界、写真/下書き保持、暗号化backup/reload、保管庫の初期設定・誤入力・解除・復元中断を検証しました。画面幅320/375/390/768/1280と、保管庫の狭い縦画面で確認。service workerキャッシュ更新・通知用4モジュールのprecache・保管庫非操作を検証しました。

既存VMテストには保存transactionとdraft revisionの依存を追加し、ブラウザー通信モックには通知config/inboxの停止応答を追加しています。旧通知helperの比較は未使用helperの回帰確認であり、新通知snapshotの仕様検証とは別です。

## 更新と復旧

vault.js、CSS、アイコン、manifestは維持します。保管庫・IndexedDB・localStorageの初期化はしません。更新時にアプリの削除や再インストールは不要です。service workerの資産キャッシュ名だけを更新します。

問題時はWorkerを同じDO/reader/ACKを保持する停止版のままにし、フロントもprotocol 4と安全な保存/ACKを保持した修正版へ差し替えます。旧フロントやDO導入前Workerへの単純差戻しは推奨しません。履歴・保管庫を消す操作を復旧に使いません。

実iPhoneでの更新、実Cloudflare通知受信、実モデル判断、実Push表示はこのローカル検証には含みません。複製端末IDや古いbackupのcontext sequence復元には既知の制約があります。実通知試験・生成開始は別工程です。

## 2026-10-22 旧履歴IDの互換修正

数値・欠落・nullの旧履歴IDで通知スナップショット作成が失敗する問題を修正。送信用の派生コピーだけに安定した文字列参照IDと由来を付け、端末の元ID・本文・順序や通知受領IDは変更しません。不正な受領通知IDや未知形式は引き続き拒否します。非同期変換中にOFFまたはロックされた場合、古い有効化要求を送信しません。SWの資産キャッシュ名を更新します。

互換IDは通知文脈内の参照です。同文重複記録の挿入・削除や本文編集では変わる場合があり、永続的なログID移行ではありません。空履歴や実RP未実施そのものを拒否する変更ではありません。

ローカルの合成データで互換ID5群、保存・受信・復旧・文脈・HTTPサイズ境界・キャッシュ検証を通過。コピー操作とHERE配色のブラウザー回帰も実行。サーバーactiveは管理側で確認済みですが、本修正後の端末からの通知同期・実モデル・Pushの一連の動作は未検証です。このリリースはWorker・Cloudflare設定を変更しません。
