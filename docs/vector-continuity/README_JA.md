## 変更

- HERE/COMMSの送信履歴では、文面による独立除外を停止。「OK」も、接続テストらしい質問と「通信成功」の返答も原文を保って参照する。明示source:testの記録は除外し、一意な同一モードexchangeIdで質問・返答を検証できる場合のみ組全体を除外。原文は削除しない。IDのない古い記録の相手は推測せず残るため、明示テストの片側だけが残る限界はある。文面だけでテストや不明な記録を有効RP・無効RPと自動認定しない。各記録に出典ID、モード、元のsource、交換ID、実保存日時と有効性未判定の表示を付ける。保存原文や人物の知識状態を書き換えない。
- 成功した新規送信の質問・返答に共通exchangeIdを追加。元の配列、個別ID、バックアップ形式は維持。明示IDが同じで同一モードの質問・返答が一意な場合のみ組にする。モード混在・通知挿入・端末時計ずれによる順序逆転でも、質問→返答を一組で選ぶ。組の選択順は日時ソート後の最後の記録位置。元の日時はそのまま表示する。
- 古い記録・重複ID・単独通知は勝手に組にしない。既存履歴は上限境界で返答だけになる可能性が残る。旧通信アーカイブは今回も参照対象外。
- BACKSTAGEは共有履歴と自身の相談を分離して参照し、登録資料と現在地・共有メモも出典付きのJSONとして渡す。共有履歴は引用参照としてuser/content表現にし、元の話者を本文に保持。相談内容・下書きはHERE/COMMSへ追加されず、提案の自動採用もない。
- 現行Workerの資料インターフェースはinstructionsのみのため、参照資料は同フィールド内で相談方針とは区切ったJSONデータとして送る。別のAPIロールによる隔離ではない。資料中のRP指示を相談役への指示として実行しないよう明示するが、実モデルの遵守は未確認。
- 通知用フィルターは旧処理を専用関数に分離しただけ。通知payload同値試験を実施。通知側の短文除外・孤立返答問題、別管理の現在地は未解決。通知の時刻、状態、購読、送信処理は変更しない。
